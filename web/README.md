# CoupFE-EDA website and TSV field workbench

This directory builds two browser surfaces from one React/Vite source tree:

- The default route is the public project website. Its featured result is a
  retained CoupFE axisymmetric TSV field with raw arrays, a solver-derived
  contour, a nine-state load-sweep video, numerical comparison, and provenance
  links. A separate evidence section features a checked partitioned ETV
  comparison, then keeps one representative stateful 3-D solder result and one
  explicitly analytic TSV-to-device screen in a compact proof register. The
  design-linked variant of the same solder block remains retained but is not
  repeated in that register. The rest of the site presents checked
  examples, the retained 526,338-DOF scaling record, and explicit evidence limits.
- `?surface=workbench` opens the TSV field explorer. On GitHub Pages it reads
  and validates the retained `field.json`; it can switch near/full-domain
  views, show a mesh overlay, probe displacement and both recovered stress
  components, and inspect each solved load state. In an explicit local API
  build, the same route also exposes one server-approved Run action.

There is no mock solver or simulated run lifecycle in the public build.
GitHub Pages is static and cannot execute Python, CoupFE, OpenROAD, MPI, or a
finite-element solve. It explores retained output generated by the repository
runner. Moving the load-state control or playing the video visits nine actual
independent static CoupFE solutions; it does not integrate physical time or
interpolate new physics.

The authoritative claim boundary is:

> Axisymmetric plane-strain thermoelastic component verification against the
> declared Lamé equation. It is not a finite-depth 3-D TSV, near-surface device
> field, experimental validation, keep-out-zone signoff, or transient cooling
> simulation.

## Requirements

- Node.js 22.22.2, as pinned in [`.nvmrc`](.nvmrc)
- npm
- Python 3.10 or newer, the pinned CoupFE Core checkout, and the optional
  workbench dependencies only when generating the field or running the local

## Refresh the simulation evidence

The public evidence section does not use stock, generated-concept, or
CoupFE-Cardiac simulation media. The renderer executes CoupFE-EDA's
`solder_3d_cycle`, `design_linked_solder_screening`, and
`etv_partitioned_cycle` runners and refuses to publish when
their numerical oracles fail. The website promotes the ETV comparison as its
featured result and shows the baseline solder field as the representative 3-D
FE result. It does not repeat the design-linked result in the proof register
because that run uses the same 3 × 3 × 2 block. The TSV device map comes from
the separate CoupFE-EDA analytic screening runner and remains labeled as
synthetic integration evidence, not FE output.

The renderer accepts either the exact clean CoupFE checkout selected by
`setup.sh` or a PEP 610 VCS installation of that same revision whose installed
Python sources still match their wheel `RECORD` hashes. This means the existing
CoupFE-Cardiac virtual environment can provide the shared pinned Core without
using any Cardiac data:

```bash
cd web
PYTHON=/path/to/CoupFE-Cardiac/.venv/bin/python npm run refresh:media
PYTHON=/path/to/CoupFE-Cardiac/.venv/bin/python npm run refresh:tsv
```

`refresh:media` writes three accessible SVGs under
`public/generated/simulation-media/` and a source/oracle/artifact hash contract
at `contracts/simulation-media.json`. The first solder heatmap exposes all 18
Hex8 element values as two exact 3 × 3 layers. The design-linked figure remains
available as retained evidence and records the stable synthetic joint identity
and distance-to-neutral-point handed to another 18-element solder result. The
ETV figure keeps energy and temperature in separate panels and distinguishes
quasisteady from lumped-transient assumptions by both color and pattern.

## Check and preview the public site

From this directory:

```bash
npm ci
npm run check
npm run dev
```

Open the URL printed by Vite. The website is the default route; append
`?surface=workbench` for the retained field explorer.

`npm run check` verifies repository-backed display data and retained evidence,
type-checks the strict TypeScript project, runs frontend tests, prepares public
assets and legal notices, and builds `dist/`.

To reproduce the GitHub Pages base path locally:

```bash
VITE_BASE_PATH=/CoupFE-EDA/ VITE_COUPFE_BACKEND=retained npm run check
VITE_BASE_PATH=/CoupFE-EDA/ VITE_COUPFE_BACKEND=retained npm run preview
```

[`coupfe-workbench-pages.yml`](../.github/workflows/coupfe-workbench-pages.yml).

publish the static site at
<https://tengzhang48.github.io/CoupFE-EDA/>.

## Retained real-field evidence

The fixed case is `axisymmetric_tsv_thermoelastic_field_v1`: a 30 µm copper
TSV, uniform `ΔT = -400 K`, 300 µm outer radius, 2,400 radial Line2 nodes,
2,399 elements, and one displacement unknown per node. The runner calls
`coupfe.newton_solve`, retains nodal radial displacement and element-center
`sigma_rr`/`sigma_theta`, and checks the radial stress at 20 µm against the
declared published Lamé equation. The retained result is approximately
354.172 MPa versus 353.948 MPa, a 0.06334% difference against a 3% threshold.

The source runner is
[`examples/tsv_axisymmetric_field/run.py`](../examples/tsv_axisymmetric_field/run.py).
After installing the pinned Core with `./setup.sh`, its only case-facing CLI
argument is the required output directory:

```bash
python examples/tsv_axisymmetric_field/run.py \
  --output-dir /tmp/tsv-axisymmetric-field
```

It writes exactly:

- `field.json`: topology, mesh/connectivity/regions, the final full-resolution
  field, and full arrays plus solver/comparison evidence for prescribed loads
  `0, -50, ..., -400 K`;
- `summary.json`: fixed inputs, mesh/DOF counts, FE/Lamé values, Newton residual
  telemetry, 40-hex EDA/Core revisions, and the normalized command contract;
- `contour.svg`: a deterministic axisymmetric reconstruction derived from the
  recovered final field.

The retained website bundle adds `load-sweep.webm`, rendered only from those
nine solved states with no interpolation between solved load states. Its
`visual-evidence.json` binds exactly four artifact roles—raw field, summary,
image, and video—to byte sizes and SHA-256 hashes, and records revisions, field
semantics, the fixed command, and renderer configuration. The manifest itself
is not one of the four declared artifacts. See the
[example guide](../examples/tsv_axisymmetric_field/README.md) and
[evidence validator](../eda_multiphysics/visual_evidence.py).

[`site-data.json`](site-data.json) is a reviewed display manifest, not an
independent source of engineering truth. The build copies the retained bundle
from `examples/tsv_axisymmetric_field/retained/` only after repository-data
checks pass. The explorer additionally rejects a field record with the wrong
case, claim boundary, topology, array sizes, non-finite values, region labels,
load ordering, solve kind, or failed comparison/convergence record.

## Run the connected local workbench

The connected workflow performs the same real CoupFE computation, so install
the pinned Core and the loopback API dependencies from the repository root:

```bash
./setup.sh
python -m pip install -e '.[workbench]'
coupfe-eda-workbench --repository-root .
```

The service binds to `127.0.0.1:8000` by default and refuses a non-loopback
host. In a second terminal:

```bash
cd web
npm ci
npm run dev:api
```

Open the Vite URL with `?surface=workbench` appended. Vite proxies `/api` to
the local service.

For one same-origin local process, build the API frontend and let FastAPI serve
it:

```bash
cd web
npm run build:api
cd ..
coupfe-eda-workbench --repository-root . --web-dir web/dist
```

Then open <http://127.0.0.1:8000/?surface=workbench>.

The current connected identifiers are:

| Contract field | Value |
|---|---|
| Project | `coupfe-eda-local` |
| Active design | `tsv-axisymmetric-field-v1` |
| Browser workflow | `tsv_axisymmetric_field` |
| Server executor | `tsv.axisymmetric-field.v1` |
| Server-owned driver | `examples/tsv_axisymmetric_field/run.py` |
| Retained oracle | `examples/tsv_axisymmetric_field/expected_results.json` |

The browser submits only project, design, workflow, and idempotency identifiers.
It never submits an executor key, command, driver path, case parameters, output
root, environment, or timeout. The server owns those values and validates the
runner's strict JSON, fixed inputs, exact array shapes, nine actual solve
records, residual acceptance, Lamé comparison, source identity, and oracle
tolerance before publishing success.

Each successful local run retains `field.json`, `summary.json`, `contour.svg`,
`stdout.txt`, and `stderr.txt`, plus a service-created `manifest.json` with
their hashes, the driver/oracle identity, elapsed executor time, and clean/dirty
EDA tree state. This local manifest is distinct from the public
`visual-evidence.json`; the connected executor does not render the website
video. A dirty flag does not retain or reproduce the dirty diff.

The queryable run index is process memory. Successful run directories remain
on disk after shutdown, but restart does not re-index them. Failed diagnostics
remain under the server-owned run root and are not downloadable through the
artifact endpoint.

The CLI is source-checkout based: `--repository-root` must contain the connected
snapshot, runner, oracle, and Git metadata. The wheel alone is not a
self-contained GUI or evidence bundle. The local API is unauthenticated and is
appropriate only for one trusted local checkout—not network or multi-user use.

## Commands

| Command | Purpose |
|---|---|
| `npm run check:data` | Fail when displayed records, paths, boundaries, or retained evidence drift from repository sources |
| `npm run prepare:data` | Check data, then copy the retained field bundle and legal files under `public/` |
| `npm run dev` | Public website plus read-only retained real-field explorer |
| `npm run dev:api` | Frontend development against the loopback real-solver service |
| `npm run typecheck` | Strict TypeScript check |
| `npm run test` | One Vitest run |
| `npm run build` | Checked static/retained production build |
| `npm run build:api` | Checked connected production build |
| `npm run check` | Type-check, test, prepare data, and build the public site |
| `npm run refresh:media` | Rerun the solder, design-linked solder, and ETV examples; verify their oracles; and refresh accessible simulation SVGs plus their hash contract |
| `npm run refresh:tsv` | Refresh the separate synthetic TSV-to-device screening artifacts; it does not regenerate the axisymmetric field bundle |
