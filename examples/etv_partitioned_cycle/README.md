# Partitioned SAC305 thermo-viscoplastic cycle

This runnable example calls the public
`eda_multiphysics.etv_fe.thermoviscoplastic_comparison` API. It compares two
temperature assumptions that drive the same spatial, plane-strain SAC305 Anand
mechanics calculation:

- **quasisteady:** chamber temperature plus the steady Joule-heating offset;
- **lumped transient:** one uniform local temperature advanced by backward
  Euler with lagged inelastic-heating feedback.

This is an explicitly partitioned model comparison, not a monolithic
electrical–thermal–mechanical element.

## Inputs and configuration

- generated geometry: a 0.1 mm square. The default 2 × 2 Quad4 mesh is the
  fast smoke-oracle configuration (nine nodes and 18 displacement degrees of
  freedom). The public website evidence is generated explicitly with
  `--mesh-size 20`: 400 Quad4 elements, 441 nodes, and 882 displacement degrees
  of freedom;
- mechanical boundary conditions: the bottom edge has `ux = uy = 0`, the top
  edge has prescribed `ux = gamma H` and `uy = 0`, and the lateral sides are
  traction free;
- material: non-aged SAC305 Anand fit from Motalab et al., plus project-model
  elastic inputs `E = 43,000 MPa` and `nu = 0.40`;
- temperature history: two endpoint-inclusive −40 → 125 → −40 °C cycles;
- periods compared: 1600 s and 1 s, with eight increments per cycle;
- CTE mismatch: 20 × 10⁻⁶ K⁻¹ and `L_D / h = 6`;
- thermal conductance density: 8 × 10⁶ W/(m³ K);
- volumetric heat capacity: 1.6 × 10⁶ J/(m³ K); and
- Joule density: computed at runtime from the average current density for the
  documented 1.7 A, representative 250 µm bump context and
  `rho_e = 13.3e-8 ohm m`.

Run from the repository root after `./setup.sh`:

```bash
python examples/etv_partitioned_cycle/run.py
python examples/etv_partitioned_cycle/run.py --check
python examples/etv_partitioned_cycle/run.py --mesh-size 20 --check
```

The commands write deterministic JSON only to standard output and do not create
source-tree files. With the default 2 × 2 smoke mesh, `--check` reads
`expected_results.json`. With `--mesh-size 20`, it reads
`expected_results_20x20.json`, which is the oracle used for the public website
evidence. Each check compares selected energies, temperature paths, mesh and
retained mechanics data, verifies that all four solver records remain inside
Core's residual-acceptance limit, and exits nonzero on a mismatch. Independent
SHA-256 values in each oracle also bind the retained mesh, all four second-cycle
state histories, the two displayed fast-cycle fields, and their end-state
displacements.

The 20 × 20 command solves four two-cycle cases and is intentionally kept out
of the fast test suite. The default 2 × 2 check remains the routine CI smoke
path; fast CI checks the already-retained 20 × 20 public record against its
independent oracle without repeating the long solve.

## Output meaning

Each period reports both temperature models. `cycle_dW_MPa` contains the
increment-summed, equal-volume mean of top-layer Gauss-point inelastic
energy-density increments; 1 MPa equals 1 MJ/m³. The default 2 × 2 smoke-oracle
second-cycle values are approximately:

| Period | Quasisteady dW | Lumped-transient dW | Relative difference |
|---|---:|---:|---:|
| 1600 s | 0.478647 MPa | 0.478343 MPa | −0.0634% |
| 1 s | 0.760818 MPa | 0.252229 MPa | −66.85% |

The separately checked 20 × 20 public-evidence values are:

| Period | Quasisteady dW | Lumped-transient dW | Relative difference |
|---|---:|---:|---:|
| 1600 s | 0.197122 MPa | 0.197003 MPa | −0.0605% |
| 1 s | 0.286218 MPa | 0.108291 MPa | −62.16% |

For the 20 × 20 fast case, the transient peak is 98.58 °C, compared with
144.94 °C for the quasisteady treatment. The corresponding 2 × 2 smoke values
are 98.60 °C and 144.94 °C. In both configurations the difference is a
model-sensitivity result. The solver records report the largest iteration
count and residual measures for each run; state advances exactly once after
each accepted mechanical increment.

Each model record also retains the nine solved states of its second cycle:
cycle phase, chamber and uniform local temperature, the nodal displacement
vector, per-element energy-density increment, and accumulated per-element
energy density. The mesh coordinates and connectivity accompany those states.
The 2 × 2 displacement vector has 18 components; the 20 × 20 record has 882.

The reported top layer is mesh-specific. It contains two elements and spans the
upper 50 µm for the 2 × 2 smoke mesh; it contains 20 elements and spans the
upper 5 µm for the 20 × 20 website mesh. Consequently, the two configurations
do not define a mesh-convergence comparison: changing the mesh also changes the
physical depth of the aggregation region.

The public figure generated by `web/scripts/render-simulation-media.py` uses
the checked `--mesh-size 20` record directly. It shows the one-second uniform
temperature paths and the actual second-cycle accumulated element-mean `dW`
fields. Both thermal treatments use one common color scale, and the renderer
does not smooth or interpolate the 400 element values. The fields are
mechanical energy-density output, not spatial temperature contours; the reduced
thermal model has one uniform local temperature per increment. The top-edge
`ux` value is a prescribed boundary displacement, while the free interior
degrees of freedom and inelastic-energy density are solved responses.

The runner is an **example**. `expected_results.json` provides the fast 2 × 2
smoke regression, while `expected_results_20x20.json` provides the selected
20 × 20 public-evidence regression. Neither is a measured benchmark or a
solver-performance benchmark.

## Provenance and references

The geometry, mesh, cycle, and coupling assumptions are generated by this
project. The Anand constants follow Motalab, Cai, Suhling, and Lall,
“Determination of Anand Constants for SAC Solders Using Stress-Strain or Creep
Data,” ITherm 2012, pp. 910–922, doi:10.1109/ITHERM.2012.6231522, with the
non-aged fit documented in Motalab's 2013 Auburn dissertation. The elastic
modulus and Poisson ratio are separate representative project-model inputs.
The current-density context follows Dandu, Fan, Liu, and Diao, “Finite element
modeling on electromigration of solder joints in wafer level packages,”
*Microelectronics Reliability* 50(4), 547–555, 2010,
doi:10.1016/j.microrel.2009.12.003; the public model uses a representative
parametric bump and is not a geometry-matched reproduction. See
[`../REFERENCES.md`](../REFERENCES.md) and
[`../../docs/theory.md`](../../docs/theory.md) for the wider evidence map and
equations.

## Limitations

The heat feedback is spatially uniform, lagged by one increment, and uses a
unit Taylor–Quinney fraction. The square block is idealized, and `L_D / h = 6`
is a mismatch-loading parameter rather than modeled bump or package geometry.
The 20 × 20 website result is one selected mesh, not a refinement series. The
comparison does not establish a monolithic `phi-T-u` formulation, a stabilized
cycle, mesh or load-step convergence, a real device or package oracle,
experimental validation, crack location, or predictive life. The results show
what the implemented reduced models do for the stated inputs only.
